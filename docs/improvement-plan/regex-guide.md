# ریجکس برای سیستم‌های بانکی ایران — راهنمای ساده

> **هشدار مهم:** هیچ بانک ایرانی قالب پیامک یکسان یا مستندشده‌ای ندارد. قالب‌ها بین بانک‌ها، بین شعبه‌ها، و حتی با گذر زمان فرق می‌کنند. پس **هرگز** یک ریجکس بزرگ ننویس؛ یک **پارسر چندلایه** بساز که با نمونه‌های واقعی تنظیم می‌شود.
>
> این فایل مرجع است، نه فاز. برای استفاده بگو: `پارسر SMS رو طبق regex-guide بساز`

---

## ۱. چهار مشکل اصلی (اول این‌ها را بفهم)

| # | مشکل | چرا خطرناک است |
|---|------|----------------|
| ۱ | **ریال در برابر تومان** | بانک‌ها تقریباً همه **ریال** می‌فرستند. اگر مستقیم ریال را نمایش دهی، همه مبالغ ۱۰ برابر بزرگ نشان داده می‌شوند. اگر تقسیم بر ۱۰ کنی و بانکی تومان فرستاده باشد، ۱۰ برابر کوچک می‌شود. **این بزرگ‌ترین منبع باگ است.** |
| ۲ | **ارقام فارسی و عربی** | `۰۱۲۳۴۵۶۷۸۹` (فارسی U+06F0) و `٠١٢٣٤٥٦٧٨٩` (عربی U+0660) و `0123456789` (لاتین) همه ممکن است. باید نرمال‌سازی کنی. |
| ۳ | **جداکننده هزارگان** | `1,250,000` یا `۱٬۲۵۰٬۰۰۰` (U+066C ممیز هزارگان) یا `1٬250٬000` — همه یک معنی دارند. |
| ۴ | **فاصله‌های نامرئی** | نیم‌فاصله (ZWNJ U+200C) در «برداشت‌شده» یا «کارت‌به‌کارت». ریجکس `.*` با `\s` ممکن است خطا بدهد. |

## ۲. گام صفر — نرمال‌سازی ورودی (قبل از هر ریجکسی)

این مرحله **الزامی** است و ۸۰٪ مشکلات بالا را حل می‌کند:

```dart
String normalizeBankSms(String raw) {
  var s = raw;

  // ۱) ارقام عربی → فارسی
  s = s.replaceAllMapped(
    RegExp(r'[٠-٩]'),
    (m) => String.fromCharCode(m.group(0)!.codeUnitAt(0) - 0x0660 + 0x06F0),
  );
  // ۲) ارقام فارسی → لاتین
  s = s.replaceAllMapped(
    RegExp(r'[۰-۹]'),
    (m) => String.fromCharCode(m.group(0)!.codeUnitAt(0) - 0x06F0 + 0x30),
  );
  // ۳) جداکننده هزارگان (کاما لاتین + ممیز عربی U+066C) حذف
  s = s.replaceAll(RegExp(r'[,٬٫]'), '');
  // ۴) نیم‌فاصله → فاصله معمولی (اختیاری؛ گاهی بهتر است بماند)
  s = s.replaceAll('‌', ' ');
  // ۵) ی/ک عربی → فارسی
  s = s.replaceAll('ي', 'ی').replaceAll('ك', 'ک');

  return s;
}
```

بعد از این تابع، می‌توانی با اطمینان فرض کنی ورودی فقط رقم لاتین و حروف فارسی استاندارد دارد.

## ۳. بلوک‌های سازنده (Building Blocks)

```dart
/// اعداد (بعد از نرمال‌سازی فقط لاتین)
final rDigits   = r'\d+';
final rAmount   = r'\d+(?:[.,]\d+)?';      // مبلغ، با احتمال اعشار

/// شماره کارت ۱۶ رقمی — ممکن است با فاصله/خط‌تیره جدا شده باشد
final rCardFull = r'\b(?:\d[ \-]?){16}\b';

/// کارت ماسک‌شده: 6104****1234 یا ****1234 یا ***1234
final rCardMask = r'\b(?:\d{4}|\*){1,3}[\*\d]{0,8}(?:\d{4})\b';

/// شماره حساب (طول متغیر، ۸ تا ۲۰ رقم)
final rAccount  = r'\b\d{8,20}\b';

/// شماره شبا — با IR شروع می‌شود و ۲۴ کاراکتر دارد
final rSheba    = r'\bIR\d{22}\b';

/// تاریخ شمسی: 1403/05/12 یا 1403-05-12 یا 12/05
final rDateJalali = r'\b(\d{4})[/-](\d{1,2})[/-](\d{1,2})\b';

/// ساعت: 14:32 یا 14:32:05
final rTime = r'\b(\d{1,2}):(\d{2})(?::(\d{2}))?\b';
```

## ۴. استخراج فیلدهای اصلی

### ۴-۱ تشخیص جهت تراکنش (مهم‌ترین بخش)

به‌جای یک ریجکس، یک **لیست واژه‌های کلیدی** استفاده کن — خیلی قابل نگهداری‌تر است:

```dart
const _expenseKeywords = [
  'برداشت', 'خرید', 'خرید کارت', 'پرداخت', 'واریز به',
  'انتقال به', 'کارت به کارت', 'شارژ', 'قسط', 'بدهکار',
  'مسدودی', 'سقف برداشت', 'پرداخت قبض',
];

const _incomeKeywords = [
  'واریز شد', 'واریز به حساب', 'دریافت', 'افزایش موجودی',
  'برگشت از خرید', 'سود', 'واریز حقوق', 'بستانکار', 'برگشتی',
];

enum TxDirection { income, expense, unknown }

TxDirection detectDirection(String body) {
  final incomeHits  = _incomeKeywords.where(body.contains).length;
  final expenseHits = _expenseKeywords.where(body.contains).length;

  if (incomeHits == 0 && expenseHits == 0) return TxDirection.unknown;
  // امتیاز بیشتر برنده؛ تساوی = نامشخص (به کاربر نشان بده تا تایید کند)
  if (incomeHits > expenseHits) return TxDirection.income;
  if (expenseHits > incomeHits) return TxDirection.expense;
  return TxDirection.unknown;
}
```

**نکته:** «واریز به» = خرج (پول از حساب تو رفت)، «واریز شد» = درآمد. این دو در فارسی گمراه‌کننده‌اند؛ ترتیب چک کردن مهم است (اول `واریز به`، بعد `واریز شد`).

### ۴-۲ مبلغ

```dart
/// اولین عددی که بعد از کلمه «مبلغ» می‌آید؛ اگر نبود، اولین عدد بزرگ
int? extractAmount(String body) {
  // الگوی اولویت‌دار: مبلغ / amount / ریال
  final patterns = [
    RegExp(r'مبلغ\s*:?\s*(\d[\d.,]*)'),
    RegExp(r'برداشت\s*:?\s*(\d[\d.,]*)'),
    RegExp(r'(\d[\d.,]*)\s*(ریال|ریالی|تومان)'),
  ];

  for (final p in patterns) {
    final m = p.firstMatch(body);
    if (m != null) {
      final raw = m.group(1)!.replaceAll(RegExp(r'[.,]'), '');
      final value = int.tryParse(raw);
      if (value != null && value > 0) return value;
    }
  }
  return null;
}
```

**ریال یا تومان؟** الگوی سوم واحد را هم می‌گیرد. قانون پیشنهادی:
```dart
/// همیشه در دیتابیس «تومان» ذخیره کن (واحد اپ).
/// اگر پیامک «ریال» داشت → تقسیم بر ۱۰
/// اگر «تومان» داشت → همان‌طور
/// اگر هیچ واحدی نبود → پیش‌فرض «ریال» (چون اکثر بانک‌ها ریال می‌فرستند)
///                    و این را به کاربر نشان بده تا یک‌بار تایید کند.
```

### ۴-۳ مانده حساب

```dart
int? extractBalance(String body) {
  final p = RegExp(r'(مانده|موجودی|باقیمانده)\s*(?:حساب)?\s*:?\s*(\d[\d.,]*)');
  final m = p.firstMatch(body);
  if (m == null) return null;
  return int.tryParse(m.group(2)!.replaceAll(RegExp(r'[.,]'), ''));
}
```

### ۴-۴ شماره کارت (برای نگاشت به کارت ذخیره‌شده کاربر)

```dart
/// ۴ رقم آخر را برمی‌گرداند تا با کارت ذخیره‌شده مقایسه شود
String? extractCardLast4(String body) {
  // حالت ۱: 6104****1234
  final mask = RegExp(r'(\d{4})\s*[\*xX·]+\s*(\d{4})').firstMatch(body);
  if (mask != null) return mask.group(2);

  // حالت ۲: 16 رقم کامل
  final full = RegExp(r'\b(\d{4})[\s\-]?(\d{4})[\s\-]?(\d{4})[\s\-]?(\d{4})\b')
      .firstMatch(body);
  if (full != null) return full.group(4);

  // حالت ۳: ***1234 (فقط ۴ رقم آخر)
  final tail = RegExp(r'[\*xX]{2,}\s*(\d{4})\b').firstMatch(body);
  return tail?.group(1);
}
```

### ۴-۵ نام فروشگاه / طرف حساب

```dart
String? extractMerchant(String body) {
  final p = RegExp(r'(فروشگاه|پذیرنده|طرف حساب|به حساب|نام فروشنده)\s*:?\s*(.+?)(?:\n|$)');
  final m = p.firstMatch(body);
  return m?.group(2)?.trim();
}
```

### ۴-۶ تاریخ و ساعت

```dart
/// اکثر پیامک‌های بانکی تاریخ ندارند؛ زمان دریافت SMS را استفاده کن.
/// فقط اگر تاریخ شمسی صریح در متن بود، آن را اولویت بده.
DateTime? extractJalaliDate(String body, DateTime fallback) {
  final m = RegExp(r'\b(1[34]\d{2})[/-](\d{1,2})[/-](\d{1,2})\b').firstMatch(body);
  if (m == null) return fallback;
  try {
    return Jalali(
      int.parse(m.group(1)!),
      int.parse(m.group(2)!),
      int.parse(m.group(3)!),
    ).toDateTime();
  } catch (_) {
    return fallback;
  }
}
```

## ۵. استراتژی صحیح: پارسر چندلایه، نه ریجکس بزرگ

```
SMS خام
  ↓ [لایه ۱] normalizeBankSms()        → ارقام لاتین، بدون کاما، ی/ک یکسان
  ↓ [لایه ۲] detectBankFromSender()     → «بله»/«بانک ملت» در فیلد sender → بانک مشخص
  ↓ [لایه ۳] isTransactionSms()         → آیا اصلاً تراکنش است؟ (حذف تبلیغات)
  ↓ [لایه ۴] extractAmount()            → مبلغ + واحد (ریال/تومان)
  ↓ [لایه ۵] detectDirection()          → درآمد/خرج
  ↓ [لایه ۶] extractBalance/Card/...    → فیلدهای فرعی (اختیاری)
  ↓ [لایه ۷] validate()                 → مبلغ > ۰؟ جهت مشخص؟ → وگرنه به کاربر نشان بده
  ↓ تراکنش تاییدشده
```

**قاعده طلایی:** اگر هر لایه `null` یا `unknown` داد، تراکنش را **دور نریز** — در صف «در انتظار تایید» بگذار و به کاربر نشان بده. این کار دقت را از ۶۰٪ به بالای ۹۵٪ می‌برد چون کاربر اشتباه‌ها را اصلاح می‌کند.

## ۶. تشخیص بانک از فیلد sender (ساده‌تر از ریجکس روی متن)

فیلد `originatingAddress` پیامک معمولاً نام بانک یا سرشماره است:

```dart
const _senderToBank = {
  'بله':       'ملت',       // سرشماره بانک ملت
  'بانک ملت':  'ملت',
  'بانک ملی':  'ملی',
  'BSI':       'ملی',
  'بانک سامان':'سامان',
  'پارسیان':   'پارسیان',
  'پاسارگاد':  'پاسارگاد',
};

String? detectBankFromSender(String sender) {
  final s = normalizeBankSms(sender).trim();
  if (_senderToBank.containsKey(s)) return _senderToBank[s];
  // جستجوی زیررشته (چون گاهی «بانک ملت - شعبه X» می‌آید)
  for (final e in _senderToBank.entries) {
    if (s.contains(e.key)) return e.value;
  }
  return null;
}
```

این روش **بسیار قابل اعتمادتر** از ریجکس روی متن است.

## ۷. رد کردن پیامک‌های غیرتراکنشی

بیشتر پیامک‌های بانکی تبلیغ یا اطلاعیه‌اند:

```dart
bool isTransactionSms(String body) {
  // الگوهای واضحاً غیرتراکنشی
  final reject = RegExp(
    r'(جشنواره|قرعه کشی|وام|تسهیلات|سود تسهیلات|'
    r'مشتری گرامی.*?جهت اطلاع|پیام تبلیغاتی|'
    r'کد تایید|رمز یکبار مصرف|OTP|پویا)',
  );
  if (reject.hasMatch(body)) return false;

  // حتماً باید مبلغ داشته باشد
  return extractAmount(body) != null;
}
```

⚠️ **رمز یکبار مصرف (OTP) را هرگز ذخیره یا لاگ نکن.** این یک ریسک امنیتی جدی است.

## ۸. دام‌های رایج (حتماً بخوان)

| دام | راه‌حل |
|-----|--------|
| ریجکس `.*` با `\n` کار نمی‌کند | `dotAll: true` بگذار یا `[\s\S]*` استفاده کن |
| `\b` با حروف فارسی درست کار نمی‌کند | به‌جای `\b` از `(?<=\s|^)` و `(?=\s|$)` استفاده کن |
| `int.parse` روی مبلغ خالی کرش می‌کند | همیشه `int.tryParse` |
| مبلغ دو بار در متن می‌آید (مبلغ + مانده) و اولی انتخاب می‌شود | الگوها را **ترتیب‌دار** چک کن، نه `firstMatch` روی یک ریجکس بزرگ |
| `1403/5/12` با `\d{2}` مچ نمی‌شود | `\d{1,2}` استفاده کن |
| اعداد با اعشار فارسی `۱٬۵۰۰٬۰۰۰٫۰۰` | نرمال‌سازی باید `٫` (U+066B) را هم مدیریت کند |
| پیامک چندخطی با `\r\n` | اول `body.replaceAll(RegExp(r'\r\n?'), '\n')` |

## ۹. روش ساخت واقعی (توصیه مهندسی)

**تنها راه درست، جمع‌آوری نمونه واقعی است:**

1. **Corpus بساز:** از ۵ تا ۱۰ نفر بخواه پیامک‌های بانکی خود را (بدون شماره کارت واقعی) برایت بفرستند. یا خودت از هر بانک یک تراکنش کوچک بزن و پیامک را کپی کن.
2. **فرمت `test/fixtures/sms_samples.json`:**
   ```json
   [
     {
       "bank": "ملت",
       "sender": "بله",
       "body": "خريد کارت 6104****1234\nمبلغ: 1,250,000 ريال\nمانده: 5,000,000 ريال",
       "expected": { "amountToman": 125000, "type": "expense", "balanceToman": 500000, "last4": "1234" }
     }
   ]
   ```
3. **تست بنویس** که هر نمونه را پارس کند و با `expected` مقایسه کند.
4. **هر پیامک ناشناس** در اپ را (بدون متن خام!) به عنوان «قالب جدید» بشمار تا بدانی کدام بانک را پشتیبانی نمی‌کنی.

بدون corpus، ریجکس‌ها حدس هستند و در تولید می‌شکنند.
